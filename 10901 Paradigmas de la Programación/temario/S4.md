## diap. 3 · El Cambio de Mentalidad Declarativa
Caja central: En programación lógica, no describes cómo calcular la respuesta; cómo luce la respuesta.

**Enfoque Imperativo** (lado izquierdo, icono de engranajes)
Secuencia de pasos algorítmicos. El programador controla el flujo exacto de ejecución y la mutación del estado. Orientado al CÓMO.

**Enfoque Declarativo** (lado derecho, icono de chip/red)
Declaración de verdades y relaciones. El motor de inferencia deduce la solución de forma autónoma. Orientado al QUÉ.

## diap. 4 · La Arquitectura del Razonamiento Automatizado
[Figura: tres bloques unidos por «+» y «=»: Base de Conocimiento + Motor de Inferencia = Deducción]

**Base de Conocimiento**

- Hechos: Verdades atómicas asumidas inmutables.
```prolog
ingeniero(juan).
```
- Reglas: Relaciones lógicas condicionales.
```prolog
listo(X) :- ingeniero(X).
```

**Motor de Inferencia**
Mecanismo subyacente que aplica aplica lógica de primer orden (Modus Ponens) para deducir conclusiones mediante unificación.

**Deducción**
```prolog
?- listo(juan).
```
↓
TRUE

## diap. 7 · De la Lógica de Primer Orden a las Cláusulas de Horn
[Figura: dos paneles, «Lógica Formal» a la izquierda y «Sintaxis Prolog» a la derecha, con líneas que unen cada parte de la fórmula con su equivalente en Prolog (∧ con la coma, ¬ con \+, → con :-)]

**Lógica Formal**
```
∀ L: no_enciende(L) ∧
 ¬ enchufada(L)
 → causa(L, desenchufada)
```

**Sintaxis Prolog**
```prolog
causa(L, desenchufada) :-
    no_enciende(L),
    \+ enchufada(L).
```
(En la imagen la segunda línea del código aparece como «, no_enciende(L),» por el cruce con una línea del diagrama.)

Pie: La notación matemática rigurosa se traduce de forma uno-a-uno a código limpio, auditable y directamente ejecutable.

## diap. 8 · Taxonomía del Lenguaje Prolog
[Figura: árbol con «Términos» arriba y cuatro ramas]

- **Átomos**: Constantes simbólicas en minúscula. Ejemplo: `juan, rosa`
- **Variables**: Incógnitas dinámicas (mayúscula o guion bajo). Ejemplo: `X, Persona, _`
- **Estructuras**: Objetos complejos jerárquicos (Functores). Ejemplo: `punto(3,5)`
- **Listas**: Colecciones ordenadas con deconstrucción. Ejemplo: `[Cabeza| Cola]`

## diap. 9 · Nivel 1: Definiendo la Realidad con Átomos de Conocimiento
[Figura: árbol familiar con flechas rotuladas padre/2: Carlos → Juan, Carlos → Elena, Juan → María, Juan → José, María → Alberto]

```prolog
padre(juan, maria).
padre(juan, jose).
padre(maria, alberto).
padre(carlos, juan).
padre(carlos, elena).
```

Caja: **Asunción del Mundo Cerrado:** Para Prolog, cualquier relación que no pueda demostrarse explícitamente con estos hechos de la base de conocimiento se considera automáticamente falsa.

## diap. 10 · Anatomía de una Consulta: Constantes vs. Variables
[Figura: dos paneles; el izquierdo con ilustración de dos piezas encajando y un check, el derecho con una antena parabólica emitiendo hacia una malla de puntos]

**Tipo 1: Verificación (Booleana)**
```prolog
?- padre(juan, jose).
```
El Motor de Inferencia busca un match exacto con un hecho existente. Retorna true o false.

**Tipo 2: Búsqueda (Generación)**
```prolog
?- padre(juan, Hijo).
```
Las variables (en mayúscula) actúan como comodines. Prolog unifica 'Hijo' con cada match válido en la base.
```
Hijo = maria ; Hijo = jose.
```

Banda inferior: **El poder del Backtracking:** El punto y coma (;) es el gatillo manual, obligando a Prolog a buscar la siguiente solución alternativa.

## diap. 11 · Anatomía de una Regla Condicional
```prolog
abuelo(X, Z) :- progenitor(X, Y), progenitor(Y, Z).
```
[Figura: la regla con cuatro llamadas señalando sus partes]

- **Cabeza (Conclusión)** (señala `abuelo(X, Z)`): Lo que el sistema intentará demostrar.
- **Cuerpo (Premisas)** (señala `progenitor(X, Y), progenitor(Y, Z).`): Condiciones necesarias. Separadas por coma (AND lógico).
- **Cuello** (señala `:-`): Operador de implicación inversa; se lee como "SI".
- **Variable Puente** (señala `Y`, que aparece en las dos premisas): Se unifica internamente para conectar la relación generacional.

## diap. 12 · Nivel 2: Construyendo Puentes de Deducción (Reglas)
[Figura: tres nodos, X (carlos), Z (juan), Y (maria); flecha padre(X, Z) de X a Z, flecha padre(Z, Y) de Z a Y, y un arco grande abuelo(X, Y) de X a Y]

```prolog
abuelo(X, Y) :- padre(X, Z), padre(Z, Y).
```
- Flecha que señala `:-`: Se lee como 'SI' (condición lógica)
- Flecha que señala la coma: Se lee como 'Y' (conjunción)

Pie: **Deducción Dinámica:** Si ampliamos la base de datos de padres mañana, esta regla automáticamente inferirá los nuevos abuelos sin modificar el código.

## diap. 13 · El Motor en Acción: Unificación y Backtracking
[Figura: árbol de búsqueda. Raíz `?- abuelo(ana, Z).` con dos ramas: «Y = beatriz», que termina en una X, «Fallo de premisa (Callejón sin salida)», con flecha discontinua de retorno al nodo raíz rotulada «Backtracking (Retroceso)»; y «Y = carlos», que lleva a «Z = elena» y a un check, «Éxito (Solución Encontrada)»]

Pie: El motor explora el árbol lógico de forma top-down. Si una ruta de inferencia falla, Prolog retrocede automáticamente al último punto de decisión válido y evalúa la siguiente alternativa.

## diap. 14 · Radiografía del Motor de Inferencia en Acción
Consulta:
```prolog
?- abuelo(carlos, Nieto).
```
[Figura: árbol. Nodo `padre(carlos, Z)` con dos ramas: «Z = juan», que se bifurca en «Y = maria» (check, «Éxito: Nieto = maria») y «Y = jose» (check, «Éxito: Nieto = jose»); y «Z = elena», que acaba en una X con el texto «Fallo. No hay hechos. Retrocede.» y flecha discontinua de retroceso]

Recuadro **Backtracking Automático**: Ocurre cuando una rama falla, obligando al motor a retroceder al último punto de decisión válido para explorar alternativas.

## diap. 15 · El Poder de la Recursividad Matemática
**Definición Declarativa**
```prolog
factorial(0, 1).
factorial(N, F) :-
    N > 0,
    N1 is N - 1,
    factorial(N1, F1),
    F is F1 * N.
```

**Pila de Inferencia (Consulta: 5!)**
[Figura: dos columnas de cajas. Columna descendente, rotulada «Buscando el caso base»: N=5, N=4, N=3, N=2, N=1, N=0. Columna ascendente, rotulada «Resolviendo la multiplicación»: F=1 (junto a N=0), F=1, F=2, F=6, F=24, F=120 (de abajo arriba)]

Pie: Insight: En lógica formal, la aritmética requiere asignación forzada (operador 'is') para ejecutar el cálculo numérico, diferenciándose de la unificación estructural pura.

## diap. 16 · Nivel 3: Inmersión Recursiva (El Reemplazo de los Bucles)
```prolog
factorial(0, 1).
factorial(N, F) :- N > 0,
                   N1 is N - 1,
                   factorial(N1, F1),
                   F is F1 * N.
```
[Figura: escalera en forma de V. Bajada: «Llamada: 3», «N1=2», «Llamada: 2», «N1=1», «Llamada: 1», «N1=0», «Match con Caso Base: factorial(0, 1)». Subida: «Retorna 1 * 1 = 1», «Retorna 1 * 2 = 2», «Retorna 2 * 3 = 6», «Resultado: F = 6»]

Pie: En Prolog no existen los bucles. Todo ciclo es una inmersión recursiva hacia un caso base definitivo.

## diap. 17 · Alerta Arquitectónica: La Direccionalidad de la Aritmética
[Figura: dos paneles. Izquierdo con flecha doble entre dos nodos (bidireccional); derecho con flecha de un nodo a otro pasando por un bloque rotulado «>, is» (unidireccional)]

**Panel de Pureza — Relación Bidireccional (Pura)**
```
?- factorial(4, 24). -> true
?- factorial(5, X). -> X = 120
```

**Panel de Ruptura — Función Direccional (Aritmética)**
```
?- factorial(N, F). -> ERROR
```

Pie: **Insight:** La evaluación matemática en Prolog requiere variables instanciadas. Al usar operadores aritméticos, la pureza lógica bidireccional se rompe, forzando al predicado a actuar como una función tradicional de entrada-salida.
