## diap. 3 · La Evolución de la Lógica Pura
[Figura: línea de tiempo con cuatro hitos]

- **1936: Cálculo Lambda** — Alonzo Church. La base matemática fundamental.
- **1958: LISP** — John McCarthy. El código es dato. Estructuras de listas y notación prefija.
- **Años 70: Hope** — Universidad de Edimburgo. El pionero. Introduce el encaje de patrones y tipos de datos algebraicos.
- **1990: Haskell** — Comité Haskell. Pureza estricta, tipado estático y evaluación perezosa.

## diap. 4 · El Cambio de Paradigma: Pensar como un Matemático
[Figura: comparación de dos columnas; a la izquierda engranajes y una caja «Memoria: X» con el valor 1 tachado y 2 escrito debajo; a la derecha un diagrama X → f(x) → Y]

**Imperativo (Tradicional)**
- Efectos secundarios y mutación.
- Variables que cambian de estado.
- Control mediante bucles (for/while).

**Funcional (Matemático)**
- Inmutabilidad y pureza.
- Sin estados alterados.
- Solo depende de entradas y salidas.

## diap. 5 · Anatomía de Hope: El Pionero del Encaje de Patrones
Hope revolucionó la programación funcional al introducir la evaluación basada en la forma de los datos, eliminando la necesidad de condicionales complejos.

[Figura: una pieza con forma de casa/triángulo sobre rectángulo se clasifica hacia uno de tres huecos: Slot 1 (círculo), Slot 2 (la misma forma de la pieza, «cuadrado con triángulo») y Slot 3 (rectángulo); ilustra el encaje de patrones por la forma del dato]

```
dec clasificar : forma -> texto;

--- clasificar (circulo) <= texto1;
--- clasificar (cuadrado_con_triangulo) <= texto2;
```

## diap. 6 · El Árbol de Ejecución: Sintaxis Comparada
Toda operación matemática es un árbol. Los lenguajes funcionales difieren en cómo lo escriben.

[Figura: árbol de expresión con + en la raíz; hijos 2 y *; el * tiene hijos 3 y 4]

**Notación Prefija**
```
(+ 2 (* 3 4))
```
La función precede a los argumentos.

**Notación Infija con Tipos**
```
2 + (3 * 4)
```
Int -> Int -> Int
Evaluación estricta clásica.

**Notación Infija**
```
2 + (3 * 4)
```
Matemáticamente puro.

## diap. 7 · La Matriz de Rosetta Funcional
| | LISP | Hope | Haskell |
|---|---|---|---|
| Definición de Función | `(defun suma (a b)`<br>`  (+ a b))` | `dec suma : num`<br>`  # num -> num;`<br><br>`--- suma(a,b) <= a + b;` | `suma a b = a + b` |
| Sistema de Tipado | Dinámico (Evaluación en tiempo de ejecución) | Estricto y Polimórfico (Declaración explícita) | Estático e Inferido (Matemáticamente derivado) |
| Control de Flujo | Anidación (if, cond) | Encaje de Patrones (---) | Encaje de Patrones y Guardas (\|) |

## diap. 8 · Capacidad 1: Recursividad como Motor de Iteración
Sin bucles tradicionales, los lenguajes funcionales iteran descomponiendo el problema hasta un caso base.

[Figura: cadena de cajas apiladas «3 * Factorial(2)», «2 * Factorial(1)», «1 * Factorial(0)» y «1 (Caso Base / Condición de Parada)»; flechas de vuelta desde el caso base devuelven los valores 1, 1, 2 y 6, es decir, el resultado se propaga hacia arriba hasta 6]

## diap. 9 · Código Comparativo: Factorial
**LISP**
```
(defun factorial (n)
  (if (= n 0)
      1
      (* n (factorial (- n 1))))
```
Uso de condicional explícito (if).

**Hope**
```
dec fact : num -> num;

--- fact 0 <= 1;
--- fact n <= n * fact(n-1);
```
Reglas de deconstrucción directas.

**Haskell**
```
factorial 0 = 1
factorial n = n * factorial (n-1)
```
Enrutamiento implícito por forma.

## diap. 10 · Capacidad 2: Deconstrucción de Estructuras
Los datos inmutables no se modifican en memoria. Se procesan separando el primer elemento del resto de la lista.

[Figura: tren; la locomotora está rotulada «Cabeza (Primer Elemento)» y los tres vagones «Cola (Resto de la Lista)»]

- **LISP**: Usa funciones históricas 'car' (cabeza) y 'cdr' (cola).
- **Hope**: Usa el operador '::' (ej. x :: xs).
- **Haskell**: Usa el operador ':' (ej. x : xs).

## diap. 11 · Código Comparativo: Recorriendo Listas
Ejemplo: Sumar 10 al primer elemento de una lista estructurada.

**LISP**
```
(cons (+ 10 (car lista))
              (cdr lista))
```
[Figura: flechas desde `(car lista)` hacia «Extrae la cabeza» y desde `(cdr lista)` hacia «Extrae la cola»]

**Hope**
```
dec sumarDiez : list(num) -> list(num);

--- sumarDiez nil <= nil;
--- sumarDiez (x::xs) <= (x+10) :: xs;
```
[Figura: flecha hacia «Destructuración en patrón»]

**Haskell**
```
sumarDiez [] = []
sumarDiez (x:xs) = (x + 10) : xs
```
[Figura: flecha hacia «Separación automática»]

## diap. 13 · Transformación y Reducción: Map & Reduce
[Figura: cinta transportadora; entra la lista [1, 2, 3], pasa por una máquina con «link: (λ x -> x+5)» y sale [6, 7, 8], que cae a un embudo «REDUCE: (+)» cuyo resultado es 21]

- **LISP**: `(reduce #'+ (mapcar (lambda (x) (+ x 5)) lista))`
- **Hope**: `reduce( +, map( lambda x => x+5, lista ) )`
- **Haskell**: `foldl (+) 0 (map (\x -> x + 5) lista)`

## diap. 14 · La Síntesis: El Legado Funcional en Big Data
La inmutabilidad de 1958 y los patrones de los años 70 garantizan la seguridad del procesamiento distribuido moderno.

[Figura: «Dataset Masivo (Apache Spark)» se reparte en tres nodos, «Nodo Servidor A», «Nodo Servidor B» y «Nodo Servidor C», cada uno con «Map -> Reduce»; los tres convergen en «Resultado Agregado Seguro»]

Al carecer de efectos secundarios, las evaluaciones perezosas de funciones map/reduce pueden distribuirse a través de miles de servidores. Sin estado compartido, no existen colisiones.

## diap. 15 · Eligiendo el Dialecto Funcional
[Figura: diagrama de Venn de tres círculos solapados]

**HOPE**: El pionero académico. Estricto, explícito, y el inventor del encaje de patrones. Ideal para comprender la teoría pura de estructuras de datos.

**LISP / Scheme**: Dinámico y maleable. El código escribe código (macros). El lenguaje programable supremo impulsado por listas.

**HASKELL**: La fortaleza matemática. Tipado estático seguro y evaluación perezosa. "Si compila, funciona".
